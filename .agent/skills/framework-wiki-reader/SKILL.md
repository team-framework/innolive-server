# Framework Wiki Reader

`search_wiki`와 `read_note`로 읽은 위키 원문만 사실의 근거로 사용한다.
검색 요약만으로 결론을 내리지 않는다.

## 탐색 상태

탐색 시작 시 다음 상태를 유지한다.

- `visited`: 이미 읽기 시작한 문서 경로 집합
- `frontier`: 아직 읽지 않은 후보 문서 목록
- `deferred`: 현재 질문과의 관련성이 약해 보이지만, 재검토할 수 있는 후보 목록
- `evidence`: 사실, 출처 문서 경로, 검증 상태, 발견 경로를 기록한 장부

문서를 `read_note`로 읽기 전에 즉시 `visited`에 추가한다.
이미 `visited`에 있는 문서는 다시 읽지 않는다.

문서 링크는 `read_note`의 `resolved_links`로 실제 위키 경로를 우선 해석한다. 링크 이름만으로 경로를 확정할 수 없으면 추정하지 말고 `search_wiki`로 후보를 확인한다. 끝내 해석하지 못한 링크는 `unresolved_links`에 남긴다.

## 단일 에이전트 탐색

단순한 질문은 단일 에이전트가 탐색한다.

1. 질문을 확인해야 할 사실 단위로 나눈다.
2. `search_wiki`로 시작 문서 후보를 찾는다.
3. 답변에 직접 관련된 후보를 `frontier`에 넣는다.
4. frontier에서 가장 관련도가 높은 미방문 문서를 하나 읽는다.
5. 문서의 사실, verification, last_verified, 링크, 발견 경로를 evidence에 기록한다.
6. 새 링크 중 미방문 문서를 frontier 또는 deferred에 넣는다.
7. frontier가 비면 deferred를 다시 평가한다. 현재 근거로 답할 수 없거나 deferred 문서가 근거를 보강·반박할 가능성이 있으면 frontier로 옮겨 읽는다.
8. 모든 후보가 읽혔거나, 보류·제외 사유가 기록된 상태에서 더 읽을 관련 문서가 없을 때 종료한다.

깊이 또는 문서 수로 탐색을 중단하지 않는다. 순환은 `visited`로 방지한다.

## 서브에이전트 승격

다음 중 하나에 해당하면 서브에이전트 탐색으로 전환한다.

- 시작 문서가 여러 개이고 서로 다른 문서 갈래를 가진다.
- frontier가 여러 독립 주제로 나뉜다.
- 문서 간 사실, 날짜, 책임자, verification이 충돌한다.
- 현재 evidence만으로 답변 근거가 부족하다.

Coordinator가 `visited`, frontier, deferred, evidence의 유일한 소유자다.
Reader는 전역 상태를 독자적으로 바꾸거나 무한히 링크를 재귀 탐색하지 않는다.

Coordinator는 서로 겹치지 않는 문서 경로 묶음을 Reader에게 배정한다.
Reader는 배정된 문서만 읽고 다음 형식으로 반환한다.

- 읽은 문서 경로
- 질문과 관련된 사실과 짧은 근거
- verification 및 last_verified
- 새로 발견한 링크와 해당 링크가 필요한 이유
- 충돌하거나 불확실한 내용
- 문서를 발견한 경로

Coordinator는 반환된 링크를 합쳐 중복을 제거한 뒤, 미방문 문서만 다음 작업으로 배정한다.
충돌한 내용은 Verifier에게 배정해 원문을 다시 읽고, 어느 문서가 더 최신·검증되었는지 판단하게 한다.

## 답변 작성

답변에는 다음을 포함한다.

- 질문에 대한 결론
- 결론별 근거 문서 경로
- 충돌 또는 불확실성
- 읽지 못한 링크 또는 제외한 문서와 사유
- 필요하면 탐색 경로 요약

문서에 없는 내용을 추측으로 보완하지 않는다.
검색 결과의 excerpt는 후보 선정에만 사용하고, 최종 근거는 반드시 `read_note`로 읽은 원문에서 가져온다.

## 답변 형식

읽기 답변에서는 `####` 이하 수준의 제목을 사용하지 않는다. 제목은 `#`, `##`, `###`만 사용한다.
