# 문서 내용과 메타데이터

## 인입과 병합

위키에는 팀이 공유할 근거 있는 사실과 팀 결정을 기록한다. 현행과 다른 과거 사실에는 `[당시]`와 시점을 붙인다. 확인되지 않은 내용은 가설·미검증으로 표시한다. 할 일은 위키의 현황 문장처럼 쓰지 않는다. 사용자와만 정한 작업 방식·판단은 팀 합의로 승격하지 않는다.

기존 문서의 `question`이 같은 질문을 다루면 그 문서에 병합한다. 새 문서는 어떤 기존 질문에도 답하지 않는 경우에만 만든다. 요청 범위와 근거를 문서·섹션 단위로 정리한다. 다른 팀이 `owner`인 문서의 사실 오류는 근거를 대조해 고치되, 팀 해석·결정 변경은 책임 팀의 근거를 확인한다.

## Frontmatter

모든 위키 Markdown은 첫 줄 `---`로 시작하고 아래 네 필드를 이 순서로 둔다. 기존 문서의 추가 필드는 그대로 보존한다.

```yaml
---
domain: [server]
question: "어떤 질문에 답하는 문서인가?"
owner: server-team
verification: code-verified
---
```

- `domain`: `[product]`, `[server]`, `[ai]`, `[client]`, `[shared]`의 배열. 여러 영역이면 실제 관련 도메인을 나열한다.
- `question`: 문서 제목의 반복이 아닌 대표 질문 하나. 한국어 의문문으로 적는다.
- `owner`: 작성자가 아닌 정본을 유지하는 팀 하나.
- `verification`: `runtime-verified`, `code-verified`, `source-verified`, `team-confirmed`, `mixed-verified`, `partial`, `chat-derived`, `unverified` 중 하나.

`partial`은 본문에 중요한 미검증·불완전·노후 부분이 남았음을 뜻한다. `mixed-verified`는 여러 근거 유형이 포함된 상태다. 근거가 늘었다는 이유만으로 등급을 올리지 않는다. 사실 일부가 낡았거나 검증되지 않았다면 `partial`로 낮출 수 있다. 등급 조정도 변경 범위에 기록한다.

## 시점

`last_verified`는 문서 전체를 현행 근거로 다시 확인했을 때만 오늘 날짜로 바꾼다. 일부 섹션·오타·링크 수정에는 기존 값을 둔다. `as_of`는 본문이 설명하는 상태의 기준 시점이다. 새 관측을 반영한 경우에만 바꾼다. 두 필드 의미가 저장소 정본에서 더 구체적으로 정해져 있으면 정본을 따른다.

## 새 문서

채팅만 근거라면 `chat-derived`로 시작하고 `근거`에 날짜, 참여자, 원문 위치, 추가 확인 항목을 남긴다. 불필요한 대화 전문·비밀값·개인정보를 복사하지 않는다. 새 문서는 담당 영역의 3층 색인과 2층 허브에 연결하고, 갈래·총 문서 수를 실제 파일 수와 대조한다. 색인 체계가 변경됐으면 현재 허브를 먼저 확인한다.

절·문장에 근거와 시점을 남기며, 변동 수치는 `_현행_수치.md`만 정본으로 둔다. 다른 문서에는 그 문서를 링크한다. 자세한 팀 메타데이터 정본이 있으면 해당 문서를 함께 확인한다.
